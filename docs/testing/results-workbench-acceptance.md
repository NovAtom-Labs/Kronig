# Results Workbench Acceptance

The native Results Workbench consumes only manifest-verified `ExperimentSpec`, `CanonicalResult`,
`ValidationReport`, and bundle provenance. View selection uses axis kind, rank, shape, centering,
units, complex values, validity masks, and metadata. It never selects behavior by a named device.

Automated coverage verifies scalar metrics, curves, position profiles, indexed profile families,
heatmaps, complex response modes, compatible overlays, invalid-point gaps, transforms, zoom, pan,
crosshair inspection, structure markers, validation summaries, and CSV, SVG, PNG, and native PDF
export contracts. Passed and needs-review results both open, but their status banners and claims are
distinct. The system browser is not part of the standard result path.

Cross-platform screenshot baselines, assistive-technology passes, and large-array performance budgets
remain release qualification evidence and must be recorded per packaged target.
