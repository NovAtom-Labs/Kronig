### Important junction limitation

The original context requested aluminum contacts at 4.10 eV together with Fermi statistics.
This backend still refuses that semiconductor Schottky/Fermi combination. The researcher
explicitly chose **ideal ohmic contacts with Fermi statistics** for the successful reference.
The aluminum work function was not applied as a Schottky barrier. Do not present this run
as a faithful validation of the original metal-contact request.

The successful latest junction run uses 1 um per silicon region, uniform 1e17 cm^-3
acceptor and donor concentrations at 300 K, full carrier continuity, Fermi statistics,
constant mobility, SRH, Auger, and Slotboom band-gap narrowing. Both quasi-Fermi levels
are extracted under bias. No avalanche, self-heating, or tunnelling is claimed at 2 V.

The MOS runs apply the 4.1 eV metal gate boundary on 10 nm oxide, with 1 um p-Si at
1e16 cm^-3 and a grounded ohmic back contact. They solve Poisson and both carrier
continuity equations. Quasi-static charge differentiation and finite-frequency AC are
different measurements; the clarification answer selects one explicitly. Outputs are
per unit area. No physical contact area is invented to report absolute farads or amperes.

## Causes reproduced and changes made

### Scientific execution

1. Ordinary precision could leave a current-conservation residual even after tighter
   Newton tolerances. DEVSIM now resolves the simulator-neutral `backend_default`
   precision to native extended model, equation, and solver arithmetic. Explicit
   `standard` remains available. An unavailable extended build refuses execution.
2. Failed Newton steps could corrupt the previous converged state through Python-float
   copies. Checkpoints now restore native model copies and use bounded progressive DC
   continuation. Physical inputs and acceptance limits are unchanged.
3. Eligible grounded stationary dielectric/semiconductor stacks use an equilibrium
   initial guess, then restore and solve the original coupled carrier equations. AC
   executes with those equations restored. Interface trap/surface kinetics and nonzero
   common contact offsets are excluded from this predictor.
4. Poisson-only requested carrier densities now come from the solved native intrinsic
   carrier models, with model identities recorded.
5. A global sweep-slope ratio falsely flagged smooth exponential or saturating responses.
   The check now tests isolated local secant anomalies within valid monotonic sections.
   Masked points and direction reversals split sections. The 1000 threshold is unchanged;
   an isolated spike still fails. This check is not a substitute for physical validation.

Requested, resolved, and effective precision, all native flags, DEVSIM build information,
compiler identity, and the numerical policy version are stored in result provenance.

Adapter-only references additionally cover a 41-point -2..+2 V junction sweep and full
101-point quasi-static and 1 MHz AC MOS schedules. At +5 V, the reviewed AC reference
gives approximately 2.8957e-4 F/m^2 versus 3.4242e-3 F/m^2 for stationary charge
differentiation. A regression protects that difference, so numerical initialization
cannot silently turn finite-frequency AC into a static electrostatic calculation.

### Preparation, delay and safety

1. A previous-study reference was being inventoried without its contents. Bounded text
   reference excerpts are now available as untrusted scientific data with source hashes.
   They cannot act as instructions. Credential filenames, symlinks, known secret values,
   and conventional credential assignments are excluded or redacted.
2. Valid repository-prefixed citations could fail authority checks. Known inventory paths
   now normalize to their actual relative paths; unknown paths remain refused.
3. Structured work-function answers with explicit energy units were not recognized by
   completeness checks. Dimension checking now handles these without accepting voltage
   as energy.
4. Clarification responses could reintroduce an obsolete analysis or drop an unrelated
   confirmed one. Explicit analysis replacement is distinguished from supplying a
   frequency, geometry, or sampling value. The study-kind field changes with its
   capabilities. Repository and researcher provenance are preserved together.
5. Contact-only answers no longer authorize dropping confirmed physics models.
6. Scope validation checks selected physics, contacts, materials, equations, profiles,
   and observables as well as studies. Substitution cannot masquerade as completion.
7. A recorded zero-bias point with common contact offsets satisfies an equilibrium
   baseline requirement; a sweep without such a point does not.
8. A chat-only finish without a scientific outcome is now blocked for simulation intents,
   even if capability bookkeeping is empty. Missing results return a readable 404 rather
   than an internal server failure.
9. Large native prepared plans exceeded the SDK's 50,000-character tool-text limit.
   Model-facing text now contains the specification, digest, and artifact references.
   The complete typed plan remains available internally and on disk.
10. The actual quantity parser already accepted unit-bearing strings, but its validation
    schema did not advertise that path. The schema now describes both accepted forms.
    Canonical result serialization is unchanged. This avoids unnecessary hand-conversion
    and dimensionality guessing by the model.

There can still be provider latency and model repair calls. No fixed runtime, zero-question
promise, or fabricated “thinking” stream is introduced.

## Reproduce safely

Run from an existing developer checkout with the configured live credential. Outputs must
be new directories. The driver never clears an existing research repository.

```sh
PYTHONPATH=src .venv/bin/python scripts/verify_live_research_workflows.py \
  --prompt evaluations/prompts/exact-pn-bidirectional.txt \
  --context evaluations/prompts/himanshu-reference.md \
  --answers evaluations/answers/exact-pn-reference.json \
  --output output/my-pn-verification --deadline 600

PYTHONPATH=src .venv/bin/python scripts/verify_live_research_workflows.py \
  --prompt evaluations/prompts/exact-mos-cv.txt \
  --answers evaluations/answers/exact-mos-quasistatic.json \
  --output output/my-mos-verification --deadline 600
```

The driver approves only the test's local scientific plan. External/system permissions
are denied. An unmapped question waits for a researcher answer in the answer file; it is
not guessed. Match an exact question ID or a field-path prefix, then the file is reloaded.
Answer wording and questions may vary on later model calls.
